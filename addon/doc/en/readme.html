1. Installation and first use

1.1. System requirements

The minimum NVDA version is 2026.2 and the last tested NVDA version is 2026.3. Features other than translation do not require an internet connection. Translation requires access to Google’s online service.

1.2. Installation procedure

  1. Open the Extra Settings .nvda-addon package while NVDA is running.
  2. Review the add-on name and version in NVDA’s installation dialog, then complete installation.
  3. Restart NVDA when prompted.
  4. Open Preferences, Settings, Extra Settings. Enable the required features and apply the changes.

After an update, compare the version shown in this manual with the installed add-on version. Reinstallation is not required to change preferences. Existing bookmarks and Quick find records are stored separately from the add-on files in the extraSettings subdirectory of NVDA’s user configuration directory.

2. Finding the settings and applying changes

  1. Open the NVDA menu, then choose Preferences and Settings.
  2. Select Extra Settings, the last category in the list. Press End while the categories list has focus to reach its last entry.
  3. Use Tab to move through the options. Press Space to check or uncheck a checkbox.
  4. Apply applies changes and leaves the dialog open. OK applies changes and closes it. Cancel discards unapplied changes; it does not undo an earlier Apply.

No NVDA restart is required after changing these options. Preferences use NVDA’s configuration system and its normal saving rules. If necessary, use NVDA’s Save Configuration command to keep your choices after a restart.

2.1. Using this manual and understanding the terminology

After initial configuration, the feature chapters follow the order used in the Extra Settings category. Use the contents links to open a chapter directly. Headings and lists provide a consistent structure for screen reader navigation.

The NVDA key is the Insert or Caps Lock key configured as an NVDA modifier. A plus sign indicates that the keys are pressed together. For example, NVDA+Shift+H means holding NVDA and Shift while pressing H. Commands shown in this manual are default assignments; assignments changed in Input Gestures take precedence.

Browse mode supports navigation through the text and elements of a web page. Focus mode passes keys to application controls, such as edit fields. Features restricted to browse mode identify that requirement in their respective chapters.

All added features are unchecked on first installation and work independently. Text translation, Clipboard translation and Automatic translation are child options of the master Translation setting. Automatic translation also requires a running session, as described in the relevant chapters.

3.1. Changing assignments

Open Preferences, Input Gestures in the NVDA menu. Locate the command under NVDA Extra Settings and add or remove the required assignment. The displayed shortcut is refreshed when the Extra Settings category opens or the corresponding checkbox receives focus. No shortcut assigned is displayed when no assignment exists.

The Applications key substitute is assigned using Set key in its settings. Shortcuts specific to Quick find records are assigned in the record creation or editing dialog and apply only to the matching page or document. Web cycling and blank-line skipping have no separate activation shortcut.

Assigning a combination used by an application or another NVDA command can affect the expected action. In particular, NVDA+Shift+C is also used to define column headers in Word and Excel. If that command is required, assign a different shortcut to Inspect clipboard.

4. Enable cycling on web pages

4.1. Purpose and scope

Default: Unchecked. When enabled, browse mode quick navigation cycles through matching elements.

4.2. Forward and backward wrapping

  • Moving forward beyond the last match returns to the first match. NVDA says “Wrapped to beginning.” before reading the element.
  • Moving backward with Shift before the first match returns to the last match. NVDA says “Wrapped to end.” before reading the element.

4.3. Examples

Press H at the last heading to return to the first heading. Press Shift+B at the beginning of the page to move to its last button. The same behavior applies to heading levels, links, tables, form fields and other element types using NVDA’s shared quick navigation. Text paragraph and non-link text block navigation are also supported.

4.4. Scope and special cases

  • If the page contains no matching element, NVDA keeps its normal not-found message. No wrap message is announced.
  • If there is only one matching element, cycling returns to that same element.
  • The feature supports browsers and embedded web views using web accessibility backends. Existing NVDA navigation commands are used, including any custom keys assigned to those commands.
  • Typing in focus mode, Tab navigation and table cell navigation are outside this option’s scope.
  • Native Word and Acrobat document views are excluded. The same/different text style commands, which have no default key assignments in NVDA, do not wrap in this release.

5. Skip blank lines on web pages

5.1. Purpose and scope

Default: Unchecked. There is no shortcut for this option. In web browse mode, ordinary Up arrow and Down arrow movements skip empty lines and move the caret to the next non-blank line in the same direction, which is then read. Lines containing only spaces, tabs or non-breaking spaces also count as blank.

5.2. Enabling and using the feature

When numeric keypad navigation is enabled, the navigation functions of keypad 8 and 2 use the same behavior. Shift selection, Ctrl paragraph movement, quick navigation, say all, focus-mode editing and native editors such as Notepad keep their normal behavior. Existing selections also use NVDA’s normal movement.

Buttons, editable controls, links, images and real table cells are preserved even when their text appears empty. Visual margins that NVDA does not expose as blank lines are outside this feature. If no further non-blank line exists, the caret stays in place and its current line is read again without an extra message. This also applies at the first and last line. For example, if only blank lines follow the final non-blank line, pressing Down arrow repeats that final line. Up arrow behaves the same way at the beginning.

Searching happens only on the relevant movement key; there is no continuous scan or whole-page cache. Long runs of blank lines are examined in short chunks. A new key, focus change or disabling the option cancels a pending search. The document is never edited. When automatic translation is running, only the reached non-blank line enters its queue. Ineligible documents and unsupported text operations use NVDA’s normal navigation.

6. Announce cut, copy and paste operations

6.1. Purpose and scope

Default: Unchecked. When enabled, standard editing shortcuts produce brief announcements. The add-on first checks for a selection or available clipboard data.

6.2. Copy: Ctrl+C

If selected text or a selected item is detected, NVDA says “Copied.” A single selected character is sufficient. Without a selection, it says “No selected data was found to copy.”

6.3. Cut: Ctrl+X

If selected data is detected, NVDA says “Cut.” Without a selection, it says “No selected data was found to cut.” The selection is checked before cutting can remove it.

6.4. Paste: Ctrl+V

If the clipboard contains data, NVDA says “Pasted.” If it is empty, it says “No data was found to paste.” Files, images and application-specific clipboard formats also count as data; the check is not limited to text.

6.5. When a check cannot be completed

  • “The selection could not be checked.” means the editable control’s selection information could not be read. It does not necessarily mean nothing is selected.
  • “The clipboard could not be checked right now.” means the clipboard could not be inspected. It is not assumed to be empty.

6.6. Important details

  • These checks establish whether prerequisite data is available. They do not separately confirm that the application completed the operation. For example, selected text in a read-only field may not be cut.
  • Even when no data is found, the shortcut is passed through NVDA’s normal handling to the application. The operation is not blocked.
  • Only Ctrl+C, Ctrl+X and Ctrl+V are covered. Plain C, X and V keys and application menu commands do not trigger announcements.
  • Announcements are suppressed in input help, during gesture capture for key assignments, and in NVDA sleep mode.
  • The clipboard is not modified. Text is read transiently only to determine whether it is empty; it is never retained or logged. Selection checks inspect the range rather than reading its text content.

7. Enable speech history

7.1. Purpose and scope

Default: Unchecked. When enabled, NVDA speech text is retained only in memory. History is never saved to disk. Closing or restarting NVDA clears previous entries. Unchecking this option and applying the change also clears the cache. The option itself and the following preferences use NVDA’s normal configuration storage.

7.2. Line count

Checking the option reveals the Line count text field at the next Tab stop. Enter a whole number from 1 to 1000. The default is 100. Each speech announcement is one entry; a long announcement is not split into multiple entries. When the limit is reached, the oldest entries are discarded so the newest speech is retained.

An invalid count reports “Enter a whole number from 1 to 1000.” The settings cannot be applied until it is corrected.

7.3. Display order

The next Tab stop is Display order. Use the up and down arrows to choose:

  • Beginning to end: The newest announcement appears on the first line, with older entries below it. This is the default.
  • End to beginning: The newest announcement appears on the last line, with older entries above it.

These names use the meanings stated above in this add-on. Both additional controls are hidden and removed from the Tab order when the checkbox is unchecked. Apply your choices with OK or Apply.

7.4. Viewing history with NVDA+G

When disabled, the command reports “Enable speech history in Extra Settings first.” An empty history displays “There are no history entries yet.” Clearing it announces “Speech history cleared.” A failed copy reports “Could not copy to the clipboard.”

NVDA+G opens the history window; it does not toggle recording. If history is disabled, a message explains how to enable it. The window focuses the newest entry at the position appropriate to the display order. Use up and down arrows to move between entries.

Ctrl+C or Copy selected entry copies just the selected row. Copy all copies entries in their displayed order. Clear history clears the in-memory entries. Escape or Close closes the window. Closing the window alone does not erase history.

While the history window is active, speech used to read its interface and entries is not recorded again. Recording resumes when you switch to another application; returning to the viewer refreshes the list. Protected input fields suppress recording.

7.5. Changing the shortcut

Open Preferences, Input Gestures from the NVDA menu. In the NVDA Extra Settings category, change the assignment for Show speech history. You can add a new key and remove the old one.

The shortcut shown in the checkbox label updates when Extra Settings is reopened or the history checkbox receives focus. Multiple assignments are all listed. If every assignment is removed, the label says No shortcut assigned.

The history window’s list is labelled History entries.

8. Use instead of the Applications key

8.1. Purpose and scope

Default: Unchecked, with no shortcut assigned. If your keyboard has no Applications key, choose a convenient substitute to open the focused item's context menu.

8.2. Enabling and using the feature

  1. Check Use instead of the Applications key. The next Tab stop is the Set key button.
  2. Activate it. NVDA asks you to press the shortcut you want to use instead of the Applications key, or Escape to cancel.
  3. Press a single key or a key combination, such as F9 or Ctrl+F9. A modifier such as Ctrl, Alt or Shift alone does not complete the selection.
  4. The shortcut is detected automatically, the capture dialog closes, and the selection is announced. The Set key button also shows your selected shortcut.
  5. Choose OK or Apply to activate it. Press the shortcut and release any modifier keys to open the menu.

Escape cancels capture and keeps the previous selection. Leaving the capture window also cancels it. The captured shortcut is consumed during selection and is not sent to the application.

While enabled, the selected shortcut opens the context menu instead of performing its previous task. Selecting a letter affects typing that letter, so choose a key you do not need for other tasks. Windows-reserved combinations such as Ctrl+Alt+Delete cannot be captured. Fn is only detected through the resulting key that the keyboard sends to Windows.

Use Set key again to change the assignment. Uncheck the option and apply to restore the shortcut's usual task; the last assignment is retained. Cancel in the settings dialog discards unapplied changes. A control that does not respond to the Applications key might not open a menu.

If another shortcut capture is active, you hear “Another key capture is already in progress.” Applying without choosing a shortcut reports “Choose a shortcut using Set key first.” Holding modifier keys too long reports “Release the shortcut keys and try again.” Switching foreground windows while waiting for modifiers to be released cancels the pending context-menu action.

8.3. Command and key capture messages

The command description in input help is Open the context menu. The key capture prompt is “Please press the shortcut you want to use instead of the Applications key. Press Escape to cancel.” Cancelling reports “Key selection canceled.” After choosing a key, the confirmation for F9, for example, is “Selected shortcut: F9. Choose OK or Apply to activate it.”

9. Append to clipboard — Windows+C

9.1. Purpose and scope

Default: Unchecked. Check this option and choose OK or Apply. Select text in an editor or a browse-mode web page, then press Windows+C. The selected text is added after the clipboard's existing text, and NVDA says “Added to clipboard.” A single selected character is enough.

9.2. Enabling and using the feature

If the clipboard is empty, the first selection is copied directly. Subsequent selections are separated by a new line. No additional separator is inserted if the previous text already ends with a line ending or the new selection starts with one. Existing line endings and spaces in the selection are preserved. Paste the accumulated text with normal Ctrl+V. Normal Ctrl+C replaces clipboard contents.

If nothing is selected, NVDA says “No selected text was found to append.” Inaccessible selections are reported as “The selected text could not be read.” Password fields are excluded. A locked clipboard or write failure produces “Could not append to the clipboard.”

This feature accumulates plain text. Font, color and other rich formatting are not retained. A clipboard containing only files, images or other non-text data is preserved; copy text first. The add-on does not save the collected text to a file or log. It resides in the Windows clipboard and is subject to your Windows clipboard preferences.

A clipboard containing only non-text data reports “The clipboard contains non-text data. Copy text first.” Existing clipboard data is not overwritten in this case.

Append to clipboard keeps Windows+C as its default shortcut; Ctrl+Shift+C is not assigned by default. You can change the assignment in Input Gestures.

9.3. Changing the shortcut

In Preferences, Input Gestures, find Append to clipboard under NVDA Extra Settings. Change the default Windows+C assignment or add another shortcut. When Extra Settings is reopened or the checkbox receives focus, its label shows the current assignments. If none remain, it says No shortcut assigned.

While enabled, the assigned shortcut performs this action. Uncheck and apply to return the key to its usual task. If you also assign the same key as an Applications key substitute, that option takes precedence.

10. Announce word and character counts

10.1. Purpose and scope

Default: Unchecked. The default shortcut is NVDA+Shift+K. When enabled, this command counts only the selected text. NVDA’s browseable results window lists Sentence count, Word count, Character count and Blank line count on separate lines. Read using the arrow keys, then press Escape or activate Close to dismiss the window.

10.2. Displaying statistics for a selection

  1. Enable Announce word and character counts in Extra Settings.
  2. Select the text to count in a document or web page.
  3. Press NVDA+Shift+K and review the four counts in the results window.
  4. Press Esc to return to the document.

Change the shortcut in Input Gestures, under NVDA Extra Settings, using Announce word and character counts. The settings label refreshes when the category is activated or the checkbox gains focus. If all assignments are removed, it shows No shortcut assigned.

10.3. Counting rules

  • Only the selection is counted. The command never edits text or changes the clipboard and does not emulate Ctrl+C. Accessible selections in supported editors and web browse mode are supported. Protected text is not read.
  • Words are groups of letters and numbers. Internal apostrophes and hyphens stay in the same word; Ankara’da and e-posta each count as one word. Decimal numbers count as one group.
  • Spaces and tabs are included in the character count; line separators are excluded. Unicode code points are counted, so some combined marks and emoji can count as multiple characters.
  • A blank line is a line within the selection with no text or only whitespace such as spaces and tabs. Visual wrapping does not add blank lines. A single terminal newline does not invent an additional blank line.
  • Sentence counting uses full stops, question marks, exclamation marks and ellipses, with exceptions for common Turkish and English abbreviations, decimal numbers and links. A final unfinished text fragment counts as a sentence. Newlines alone do not end sentences. This is not a grammar parser; unusual abbreviations, lists and other languages can affect results.

Counting starts only when invoked. Large selections are counted in the background. No network connection or language download is needed. Repeated presses while counting do not start additional jobs. Disabling the option or restarting NVDA discards pending results.

10.4. Messages

  • Enable word and character counts in Extra Settings first.
  • Select some text first.
  • The selected text could not be read.
  • Text counting is already in progress.
  • The selected text could not be counted.

11. Inspect clipboard

11.1. Purpose and scope

Default: Unchecked. The default shortcut is NVDA+Shift+C. The command reads a snapshot of the current clipboard and presents it in NVDA’s browseable window. Close it using Escape or Close. Clipboard contents and copy/cut state are never modified.

11.2. Displaying clipboard contents

  1. Enable Inspect clipboard in Extra Settings.
  2. Copy the text, table, files, or folders from the relevant application.
  3. Press NVDA+Shift+C. Text, a table, or file information is displayed according to the available content.
  4. When finished, press Esc to close the window. Run the command again to inspect content copied later.

Change the shortcut in Input Gestures, under NVDA Extra Settings, using Inspect clipboard. The settings label refreshes on focus or category activation; it shows No shortcut assigned if all assignments are removed. NVDA+Shift+C conflicts with setting column headers in Word and Excel; choose another clipboard inspection shortcut if you use that command.

11.3. Text and tables

Plain text is displayed in full for reading, selection and copying. If HTML table data is also available, rows, columns and cells are preserved for NVDA table navigation. Plain text alone is not used to guess the original table structure. Malformed HTML falls back to plain text when available. RTF-only content, images and other special formats may not be supported.

Only table text and basic structure are retained; visual styling, scripts and external resources are removed. Only the copied fragment is used, not unselected surrounding HTML content. No external browser opens and no internet request is sent to retrieve content.

11.4. Files and folders

Existing files copied from applications such as File Explorer take priority over text. The window starts with Files on clipboard; folders are included in this count. Each item then shows a File number, Name, Type, Size and full Path for each item. Type descriptions come from Windows. Sizes show bytes, with a KiB, MiB, GiB or TiB equivalent where appropriate.

Folders have type Folder and size Not calculated for folders. No directory contents are scanned. If a file is inaccessible, other items still appear; its type and size show Unavailable and The file could not be accessed. It may have been moved or deleted. File contents are not opened. Virtual files without an existing filesystem path, such as some email attachments, are outside this feature.

11.5. Operation and messages

There is no clipboard monitoring. Reading and metadata queries run in the background only when invoked; network file metadata may take longer. The window shows the captured snapshot, not later clipboard changes. Run the command again to refresh. Repeated presses do not queue additional jobs. Disabling the option or restarting NVDA discards pending results. Each text/HTML format is limited to 16 MiB, and file lists to 10,000 items; exceeding a limit produces a message instead of silent truncation.

  • Enable clipboard inspection in Extra Settings first.
  • The clipboard is empty.
  • The clipboard does not contain supported text, a table or files.
  • Clipboard inspection is already in progress.
  • The clipboard content is too large to inspect.
  • The clipboard could not be read. Please try again.

12. Bookmarks

12.1. Purpose and scope

Default: Unchecked. Enable Bookmarks in Extra Settings and apply, then press NVDA+Shift+Y to open the shared list. If disabled, “Enable bookmarks in Extra Settings first.” is announced. Reassign the shortcut in Input Gestures under NVDA Extra Settings; the settings label follows the current assignment.

12.2. Creating and opening a first bookmark

  1. Enable Bookmarks in Extra Settings.
  2. Return to the web page or File Explorer folder to save and press NVDA+Shift+Y.
  3. Choose Add current location and review the suggested name, location type, and address.
  4. Make any required corrections and choose Save bookmark.
  5. Select the record in the list and press Enter. Folders open in File Explorer; web pages open in the default browser.

12.3. Creating a bookmark from the current location

Add current location: The add-on captures the web page or File Explorer folder that was active before opening the list. When detected, its name and address are filled in for review. Otherwise, “The current location could not be detected. Enter its name and address manually.” is announced and an empty editor opens. Some Explorer tabs, virtual Windows locations and browser views may not support automatic detection.

12.4. Creating a bookmark manually

Add bookmark: Enter a Bookmark name and Location type. Choose Folder or Web page. The address field is labeled Folder path or Web address according to the selected type. Browse for folder opens the Choose a folder dialog. Web addresses must begin with http:// or https://; folders require an absolute path such as C:\Documents. Network folders are supported. Save bookmark stores the record; Cancel or Esc discards the edit. Duplicate locations are rejected. An unavailable folder can be saved; access is checked when opening it.

12.5. Using the list and opening a location

Saved bookmarks: Each row contains a name and type. Search bookmarks filters by name or address; clearing the search restores all entries. Selected location shows the full address. Enter on the list or Open bookmark opens folders in File Explorer and web pages in your default browser, then closes the list. An unavailable folder produces a message and keeps its record.

Edit bookmark changes its name, type or address. Remove bookmark or Delete on the list removes only the selected saved record; it never deletes a folder or its contents. Close or Esc closes the list. Disabling the feature and applying also closes the list while retaining its records.

Changes are saved immediately to extraSettings/extraSettingsBookmarks.json in NVDA’s user configuration folder. Records survive NVDA restarts and add-on updates. Previous valid contents are kept in extraSettingsBookmarks.json.bak. A damaged file produces a warning and is not overwritten. Records contain plain text names and addresses; folder paths must also be valid on any computer to which you transfer them. There is no continuous monitoring, downloading page contents or sending bookmarks to a service. A website address is passed to the browser only when opening a bookmark.

12.6. Notifications and warnings

  • Bookmark removed.
  • Bookmark saved.
  • Bookmarks changed elsewhere. Close and reopen the list.
  • Bookmarks could not be read.
  • Bookmarks could not be saved. Your previous records have been kept.
  • Enter a bookmark name.
  • Enter a complete http or https web address.
  • Enter a folder path or web address.
  • Enter an absolute folder path, such as C:\Documents.
  • The bookmark could not be opened. Check its address or folder path.
  • The bookmarks file is damaged or unsupported. It has not been changed.
  • The folder is unavailable. It may have been moved, deleted or disconnected.
  • There are no matching bookmarks.
  • This location is already bookmarked.

13. Quick find

13.1. Purpose and scope

Default: Unchecked. Enable Quick find in Extra Settings and apply. Press NVDA+Shift+H to open saved locations for the current page or document. Reassign this main shortcut in Input Gestures under NVDA Extra Settings; the settings label follows the assignment. When disabled, “Enable Quick find in Extra Settings first.” is announced.

13.2. Creating and revisiting a text location

  1. Enable Quick find in Extra Settings.
  2. In a supported page or document, move to the non-blank text line to save.
  3. Press NVDA+Shift+H and choose Add current line.
  4. Review the Location name. Optionally use Assign shortcut to assign a combination for direct access.
  5. Choose Save location and close the list.
  6. Move elsewhere in the same page or document, then use the record shortcut or select the record in the Quick find list and press Enter.

13.3. Saving the current line

Add current line: The line at the caret is captured before opening the list. Its text becomes the initial Location name, which you can edit. Saved line is read-only. Save location commits the record; Cancel or Esc discards the edit. Duplicate locations are rejected. To save another line, close the list, move to that line, then reopen Quick find.

13.4. Assigning a record-specific shortcut

Assign shortcut: Each saved location may have an optional shortcut. The button reads Assign shortcut when unassigned and Change shortcut when assigned. Assigned shortcut is a read-only field showing the current key or No shortcut assigned. Remove assigned shortcut appears only when a key is assigned. Activate Assign shortcut with Enter or Space, then press the intended combination. The captured key appears in Assigned shortcut; use Save location to apply it. Use a letter, digit or function key with NVDA, Alt or Control. Unmodified typing/navigation keys and standard editing combinations are rejected. Visible existing NVDA and add-on assignments are checked; the same shortcut cannot be assigned twice in one document. Native application shortcuts not reported to NVDA cannot all be detected. Remove assigned shortcut clears the assignment; use Save location to apply it.

Input Help describes a record shortcut as “Go to a saved location in the current document”. A record shortcut works only while its document or page is active and Quick find is enabled. Different documents may reuse the same record shortcut. On other pages, in protected fields or while the list is open, the normal key action is preserved. Disabling the option and applying closes the list and cancels pending navigation while preserving records.

13.5. Listing, editing, and removing records

Saved locations in this document: Rows show the name, captured text line number and shortcut. Line numbers count line endings in the text exposed to NVDA; they may differ from visual wrapping or Word’s printed lines. Search saved locations filters names and saved line text. Enter or Go to location closes the list, moves the caret and reads the destination line. Edit saved location changes the name and shortcut. The editor initially focuses Location name. Tab reaches the read-only Assigned shortcut field, where the stored combination can be read; Shift+Tab goes back. This field participates in keyboard tab traversal and cannot be edited directly. Remove saved location or Delete on the list removes only the saved record. Esc or Close closes the list.

13.6. Verifying locations with repeated text

Repeated text: Records contain target text, short surrounding text, position, occurrence index and a document digest. An unchanged document allows the original position to be verified. After edits, target text and context are compared rather than blindly using the old line number. If ambiguity remains, Choose matching location lists occurrences with current text line numbers and surrounding text. Enter chooses a match; Esc cancels without moving. If missing, “The saved location was not found in this document.” is announced.

13.7. Supported documents and matching rules

Scope: The shared text adapter supports web pages, TXT documents in Notepad, Microsoft Word and supported PDF views where NVDA exposes text and caret navigation. Image-only PDFs and views without accessible text positions are unsupported. Not every PDF reader or document view offers the same access. Web records retain the complete page URL, including path, query and fragment. The document must already be open; Quick find does not open closed files or navigate to another page.

The full file path identifies a document when available. Otherwise its title and short samples from both ends of its text are used, with “This document is identified by its title and text sample because its full path is unavailable.” shown in the dialog. Renaming the document or changing its beginning/end may then hide previous records. Unsaved documents do not have guaranteed persistent identities.

Operation and storage: No continuous monitoring is used. Accessible document text is read on demand; matching runs in the background and native searches yield between short steps. A changed document or caret cancels pending movement. Limits are 1000000 document characters, 1000 characters per target line and 1000 matches, with a message when exceeded. Records are stored in extraSettings/extraSettingsQuickFind.json in NVDA’s user configuration folder; previous valid contents are kept in extraSettingsQuickFind.json.bak. Records contain the target line and short surrounding text, not a complete document copy. Nothing is sent to a translation service. Records survive add-on updates and NVDA restarts. Damaged files are not overwritten.

13.8. Notifications and warnings

  • Enter a name and a valid shortcut, or leave the shortcut unassigned.
  • Move to a non-blank text line first.
  • Press the shortcut for this saved location. Press Escape to cancel.
  • Protected fields cannot be saved in Quick find.
  • Quick find could not complete the operation.
  • Quick find is already searching.
  • Quick find is not available in this document or view.
  • Quick find location removed.
  • Quick find location saved.
  • Quick find records changed elsewhere. Close and reopen the list.
  • Quick find records could not be read.
  • Quick find records could not be saved. Your previous records have been kept.
  • Quick find supports documents up to 1000000 characters and lines up to 1000 characters.
  • Several locations match. Choose the intended location; no movement has been made.
  • The Quick find file is damaged or unsupported. It has not been changed.
  • The current line could not be saved. Return to the document and try again.
  • The document or caret changed. Run Quick find again.
  • There are no matching saved locations in this document.
  • There are too many matching locations. Use a more distinctive line.
  • This location is already saved in Quick find.
  • This shortcut is already assigned in this document.
  • This shortcut is already used by NVDA or another add-on. Choose another shortcut.
  • Use a letter, number or function key with NVDA, Alt or Control. Standard editing and navigation keys cannot be assigned.

14. Use the numeric keypad as navigation keys

14.1. Purpose and scope

Default: Unchecked. NVDA normally uses some keypad keys for text review and object navigation. With Num Lock off, this option makes eight keypad keys work as Home, End, Page Up, Page Down and the arrow keys. No separate add-on or mode-switch shortcut is needed.

14.2. Enabling and using the feature

  1. In Extra Settings, check Use the numeric keypad as navigation keys.
  2. Choose OK or Apply. No NVDA restart is required.
  3. Turn Num Lock off and use the following keypad keys.
  • 7: Home. Moves to the beginning of the line in an editor.
  • 1: End. Moves to the end of the line in an editor.
  • 9: Page Up. Moves up one page.
  • 3: Page Down. Moves down one page.
  • 8: Up arrow.
  • 2: Down arrow.
  • 4: Left arrow.
  • 6: Right arrow.

These keys use the same handling as the actual navigation keys in the current application. Combinations with Ctrl, Shift, Alt and Windows are preserved. For example, in an editor, Ctrl+numpad 7 moves to the beginning of the document; Ctrl+numpad 1 moves to its end. Shift+numpad 7 selects to the start of the line; Ctrl+Shift+numpad 1 selects to the end of the document. Results depend on the application and NVDA’s active mode.

Combinations containing the NVDA modifier are unchanged. Numpad 0 remains an NVDA modifier if configured as one. Numpad 5, decimal separator, plus, minus, multiply, divide and Enter keep their existing functions. Number entry with Num Lock on and the number row above the letters are unaffected. Keyboards without a numeric keypad do not need this option; an external keypad can be connected later.

Uncheck the option and choose OK or Apply to restore NVDA’s previous handling of the eight keys. Personal gesture assignments are not deleted, and Windows and Num Lock settings are not changed. Cancel discards unapplied changes.

Input help describes the emulated key without navigating. If a keypad key is also assigned as the Applications key substitute, that option takes precedence. Other add-ons that reassign the same keys may conflict.

Input help includes the effective navigation key name. For Home, for example, its description is “Emulates pressing Home on the system keyboard”.

15. Translation

15.1. Purpose and scope

The master Translation checkbox defaults to unchecked. The target defaults to Turkish. Uses Google ontext translation without an account, API key, Chrome or another browser. No web page opens. An internet connection is required.

  1. Check Translation in Extra Settings to reveal its options.
  2. Tab through Target language, Text translation — NVDA+Shift+T, Clipboard translation — NVDA+Ctrl+Shift+T, and Automatic translation — NVDA+Shift+O.
  3. Select Text translation, Clipboard translation and Automatic translation independently. All three share the target language. Text translation and Clipboard translation default to checked; Automatic translation defaults to unchecked. None runs with the master switch off.
  4. Apply or confirm your settings. Disabling the master switch stops both modes, clears pending work and caches, and hides their controls. Child choices and the target are preserved when the master is re-enabled. Start a new automatic session with its shortcut.

15.2. Text translation — NVDA+Shift+T

With both Translation and Text translation checked, press NVDA+Shift+T to translate and speak the current caret line or focused item text. The shortcut does not toggle the option. If manual text translation is off, an announcement asks you to enable it; automatic translation remains independent.

Uses the writing caret in editable fields and NVDA's browse-mode caret in web documents. If a readable caret line is unavailable, it uses the accessible name, value and description of the focused menu item, button or other application control. This also works in supported native documents and applications. It does not move the caret, edit the document or use the clipboard. Items without accessible text report an error; no OCR is performed.

The bundled list contains 249 supported target languages as of 19 October 2026. Source language is detected automatically. Language names follow the Turkish or English interface; opening settings does not fetch the list over the network.

Change the shortcut under Input Gestures → NVDA Extra Settings → Translate current text. The text translation checkbox reflects the effective assignments, including multiple gestures or no assignment.

Requests run in the background. A delayed result triggers one “Translating...” notice. Repeating the same pending manual request does not duplicate it. A new manual request replaces an earlier pending request and stale results are ignored; this is separate from the automatic queue.

The last 32 manual results are cached in memory. A result can be reused for 120 seconds; expired entries are removed on the next manual request. Turning off manual text translation or the master option, changing the target, or closing NVDA clears this cache. Results are not automatically copied to the clipboard.

Example in an application: Tab to an English “Save changes” button and press NVDA+Shift+T. With Turkish as the target, the button text is translated and spoken in Turkish. The same shortcut works on menu items. You do not need to select or copy text. The exact wording depends on the translation service.

15.3. Messages and limits

  • When the master option is off: “Enable translation in Extra Settings first.” If only manual text translation is off: “Enable text translation in Extra Settings first.”
  • Empty lines: “There is no accessible text here to translate.” No network request is made.
  • Protected fields such as passwords are not translated. If focus moves to a protected field while waiting, the result is not spoken.
  • The maximum input is 5000 characters. Longer lines are reported instead of being silently truncated.
  • Connection failures, timeouts and unreadable responses produce brief messages. Other NVDA functions continue working.
  • When access is limited, the add-on says “The translation service is limiting access. Try again later.” and briefly pauses new requests.

15.4. Connection messages

A failed request reports “The translation request could not be completed. Please try again.” A timeout reports “The translation service did not respond in time.” An invalid response reports “The translation service returned an unreadable response.” These messages alone do not establish that the internet connection is offline.

15.5. Text transmission and disabling

In manual mode, only the requested line or focused item text is sent to Google over HTTPS when a translation is needed. Automatic mode also sends eligible lines and focused items’ accessible names, values and descriptions as you navigate. The whole document and surrounding lines are not sent. The text is not included in a URL or written to a separate add-on log. Spoken results may appear in speech history if enabled; NVDA debug logging can also record spoken text.

The connection uses Google’s keyless web translation endpoint, rather than its official paid developer service. Endpoint or response changes may require an add-on update. Continuous availability is not guaranteed.

Uncheck the master Translation option and choose OK or Apply to stop all three modes. The target list and child controls are hidden, pending results are not announced, and new translation requests are stopped. An already running network operation ends when it responds or times out. Cancel discards unapplied changes.

15.6. Other translation messages

  • Choose a supported target language in Extra Settings.
  • Choose a target language.
  • Protected fields cannot be translated.
  • The text at the caret or focused item could not be read.
  • This text is too long to translate. The limit is 5000 characters.
  • Translation is already in progress.

15.7. Clipboard translation — NVDA+Ctrl+Shift+T

Default child selection: checked. The master Translation option is off on first installation. Clipboard translation appears below the target language when Translation is enabled. It is independent of Text translation and Automatic translation, so you can use clipboard translation alone.

  1. Enable Translation and Clipboard translation, choose a target language, then select OK or Apply.
  2. Copy the text from any application using the normal Ctrl+C command.
  3. Press NVDA+Ctrl+Shift+T. The clipboard text is translated in the background and the result is spoken. For example, copy “The settings have been saved.” and translate it into Turkish.

Change the shortcut in Input Gestures → NVDA Extra Settings → Translate clipboard text. The Clipboard translation checkbox reflects the effective assignment when the category opens or the checkbox receives focus. Removing the assignment displays No shortcut assigned.

The clipboard is read only when you invoke the shortcut; it is not monitored. The translation does not overwrite the clipboard, paste into an application or change existing clipboard contents. Line endings in plain text are preserved in the request. Files and images are not translated. If a copied table also provides plain text, only that text is used.

Each request accepts up to 5000 characters; longer text is rejected without truncation. Source language detection is automatic. The feature uses the same target language and online service as the other translation modes. Clipboard text is sent to Google over HTTPS only when the shortcut is invoked. Clipboard translation is blocked while focus is protected.

The last 32 clipboard results have a separate in-memory cache lasting up to 120 seconds. Disabling Clipboard translation or the master option and applying, changing the target, or closing NVDA clears this cache and pending requests. Disabling Text translation does not disable Clipboard translation. Late results are discarded when clipboard translation has been disabled.

  • There is no text on the clipboard to translate.
  • The clipboard text could not be read. Please try again.
  • Enable clipboard translation in Extra Settings first.

If the master option is off, you hear “Enable translation in Extra Settings first.” Length, connection, timeout and service-limit messages are shared with the other manual translation requests.

16. Automatic translation

16.1. Purpose and scope

Starting a session announces “Automatic translation on.” Stopping announces “Automatic translation off.” A full queue reports “The automatic translation queue is full.” The pause message is “Automatic translation paused. Turn it off and on to start a new session.”

16.2. Enabling and using the feature

Default: unchecked. With the master Translation option enabled, an Automatic translation checkbox appears after the target language, Text translation and Clipboard translation controls. Manual text translation need not be checked. This checkbox permits use of the shortcut. Check it and apply settings, then press NVDA+Shift+O to start or stop an automatic session. The shortcut never changes the saved checkbox. Starting captures the current line or focused item text. If the master option is off, you are asked to enable translation first; if only the automatic checkbox is off, you hear “Enable automatic translation in Extra Settings first.” No session starts and no line is sent. Checking the box alone does not start translation.

Change the shortcut under Input Gestures → NVDA Extra Settings → Automatic translation. The settings label reflects the effective gesture, including a removed assignment.

Captures NVDA caret announcements made in line units, such as Up/Down in text fields and web browse mode. When focus moves to a menu item, button or other application control, its accessible name, value and description are also queued for translation. The original text is replaced with the translation in the selected target language. NVDA's localized role and state information is spoken alongside the result without being sent for translation, so it cannot confuse source-language detection. Character and word navigation work normally. Only text exposed to NVDA is translated; no OCR is performed.

Automatic use with menus and buttons:

  1. Enable Translation and Automatic translation in Extra Settings, choose a target language, and select OK or Apply.
  2. Return to the application and press NVDA+Shift+O. You hear “Automatic translation on.”
  3. Move between controls with Tab or Shift+Tab, or navigate an application menu using arrow keys. Accessible focused item text is translated in order without pressing the manual translation shortcut for each item.
  4. Press the same shortcut again when finished. You hear “Automatic translation off.” Pending translations and the session cache are cleared.

For example, moving to “Save changes” and then “Open document” translates the two items in that order. This is not limited to web pages. Controls drawn as images without text exposed to NVDA cannot be translated.

Lines 1, 2, 3 and 4 are translated and spoken in capture order even when navigated rapidly. New lines never replace earlier queued lines. The next translation is spoken after the preceding one finishes. Later lines can continue being translated in the background. If navigation cancels speech, the interrupted translation is retained and read again. Repeated announcements of the same position are deduplicated. Returning to a line after another line reads it again; identical text on distinct lines remains distinct.

The last 256 translations are cached in memory for the automatic session. Repeated text reuses these results; new text still requires translation. Blank lines are not translated. Protected fields are not sent, and queued translations are held while focus is protected.

Stopping the session with its shortcut, or unchecking Automatic translation and applying, clears captured lines, unread results and the automatic cache, and stops its current speech. In-flight network results are ignored after closing a session. Starting again with the shortcut creates a fresh session; checking the box alone does not start one. Changing the target or disabling the main translation feature also clears the automatic session. The manual translation cache is separate.

A failed translation holds that row and subsequent rows, reports the problem and pauses capture. Toggle off and on to start a new session, clearing the old queue. Lines over 5000 characters or a queue reaching 1000 rows or 1,000,000 source characters also pause capture with an announcement; already accepted successful rows continue reading.

Text transmission: While automatic translation is on, eligible lines and focused items’ accessible names, values and descriptions are sent to Google as you navigate, without another translation shortcut for each line. The add-on does not save text or results to disk. NVDA speech history and debug logs may record spoken translations according to their settings. The checkbox permission follows normal NVDA configuration saving. The running session is not saved: after restarting NVDA, use the shortcut to start it even if the checkbox remains checked. Queued lines and cached translations never survive a restart.

17. Settings and user data

17.1. Configuration preferences

Checkbox states, the target language, and other persistent preferences use NVDA’s configuration system and its normal saving rules. The functions of Apply and OK are described in the settings chapter.

17.2. Bookmarks and Quick find records

Bookmarks are stored in extraSettingsBookmarks.json; Quick find locations are stored in extraSettingsQuickFind.json. Both files and their backups reside in the extraSettings subdirectory of NVDA’s user configuration directory. The preceding valid contents are retained in a file with the same name followed by .bak. Disabling a feature does not remove its records. Use the removal command in the relevant feature dialog to delete a record.

Migration from earlier releases: When the add-on starts, legacy bookmark and Quick find files and their .bak backups are automatically moved from the root of NVDA’s user configuration directory into extraSettings. Record contents and assigned shortcuts remain unchanged. If a different file with the same name already exists at the new location, that file remains active; the legacy file is preserved under extraSettings/legacy with a name distinguished by its content hash. Identical copies are consolidated. If migration cannot finish, files not yet moved remain in place and are retried on a subsequent start. Checkbox states and other preferences managed by NVDA continue to use NVDA’s normal configuration.

Records contain names, addresses, or document identities. Quick find records also contain the target line and short surrounding text. Consider this content when backing up or transferring these files. If a folder path or document identity changes, verify that the corresponding records still work in the new location.

17.3. Temporary data and the clipboard

Speech history and translation caches are held in memory and do not survive an NVDA restart. A running automatic translation session and its queued lines also end at restart. Text collected with Append to clipboard resides in the Windows clipboard and follows Windows clipboard storage preferences.

17.4. Ontext translation

A line or accessible focused item text is sent to Google when translation is required. During an automatic translation session, eligible lines and focused items’ accessible names, values and descriptions are sent as you navigate. The Translation and Automatic translation chapters explain transmission scope, memory use, protected fields, and service limits.

18. Troubleshooting and support

18.1. When a command does not respond

  1. Verify that the corresponding feature is checked in Extra Settings and that Apply or OK has been used.
  2. Check the current assignment in Input Gestures. The shortcut may have been changed or removed.
  3. Confirm that the active field is within the feature’s supported scope. Text counting requires a selection; text translation requires a readable line or accessible item text.
  4. Compare NVDA’s announcement with the explanation in the relevant feature chapter.

18.2. When a Quick find shortcut is used on another page

Saved locations are matched to their page or document. Pressing a saved shortcut on another page does not navigate to the original page’s record; the key performs its normal action. Separate locations can be saved for different pages, and those pages may reuse the same shortcut. A change to the saved page’s address can also affect matching.

18.3. When translation does not return a result

Check the master Translation setting, the required child option, and the target language. For automatic translation, start a session using its shortcut. Follow the specific explanation for connection, timeout, or service limit messages; these messages do not all indicate the same condition.

18.4. Requesting support

Include the add-on and NVDA versions, application name, enabled feature, shortcut, steps taken, and announcement received. Do not include passwords or personal document contents. Send suggestions, comments, or issue reports to m.aykurt38@gmail.com.

19. Frequently asked questions

19.1. Automatic translation is checked but nothing starts. What should I do?

The checkbox is permission to use the feature. Apply it, then press the assigned automatic translation shortcut, NVDA+Shift+O by default. The same shortcut stops a running session without unchecking the box. After restarting NVDA, start the session with the shortcut again.

19.2. How do I turn off a feature?

Return to Extra Settings, uncheck the relevant checkbox, then press OK or Apply. You can leave other options enabled.

19.3. Letters are being typed instead of navigating a page. What should I check?

Web cycling uses NVDA’s browse mode quick navigation. In focus mode, letters are normally passed to the application. To navigate the page, check that browse mode and single-letter navigation are enabled.

19.4. How can I open this help again?

Open the help for Extra Settings in NVDA’s add-on management interface. The English file is doc/en/readme.html; the Turkish file is doc/tr/readme.html.

The interface follows NVDA’s language setting. Turkish and English are supported; other languages use the English source strings. Restart NVDA after changing its language so the add-on can load the corresponding translations.
